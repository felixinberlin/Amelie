# EuroBirdCast Bird Weather — reproducible fusion pilot

**Status: data quality gate failed. No model fitted, no skill score, no live forecast.**

This runnable Python standard-library pipeline combines a bounded historical German radar subset with matching ERA5 weather. It implements the planned chronological model comparison behind a gate; it does not pretend the full scientific record has been imported.

From repository root:

```sh
python3 07-demos/eurobirdcast/forecast/prepare.py
python3 07-demos/eurobirdcast/forecast/evaluate.py
npm run test:bird-forecast
```

Preparation downloads three compressed Aloft months for Protzel (`depro`), October 2021/2022/2023, and three corresponding weather JSON responses. Each file is capped at 25 MB; cache is `/tmp/eurobirdcast-forecast-cache`. Source URLs, raw SHA-256, byte lengths, retrieval timestamps and licenses are retained in `dataset.json`. Delete only these named cache files if intentionally fetching a new upstream version; compare hashes and record the change. The repository contains derived summaries, not the large raw archive. Re-evaluation of the committed dataset is offline.

The frontend consumes `src/data/birdForecastExperiment.json`, generated by `evaluate.py`. The frontend shows the quality gate, or the historical comparison table if an eligible dataset passes. A changed extraction protocol and any resulting scientific interpretation must be reviewed before publication. The current result is explicitly a data quality report.

## What was measured

Protocol **density-v2** corrects v1 (preserved in Git commit 53d8e63): `gap` concerns velocity support and does not invalidate density. Target: time-slot mean integrated bird-density estimate in **1000–2000m AMSL**, five distinct 200m layers. Require finite nonnegative `dens`, positive `n_dbz`, and finite `sd_vvp` and recorded threshold. Set density to zero below that threshold, following bioRad; missing discrimination stays missing, never zero. Average distinct five-minute scan profiles within each nominal quarter-hour, then average slots. These are real scans, not processing versions. No expert biological validation is implied.

Each target night starts at 18:00 UTC and ends at 06:00 UTC the next day. This is a fixed clock proxy, not astronomical darkness. October 1–30 yields 30 complete candidate windows per year. At least 36 of 48 quarter-hour slots must contain complete accepted layers. Missing slots are not filled with zero; the reported target averages observed slots only. Rain and processing gaps may select nights non-randomly. This gate must be checked for resulting bias before scientific use.

ERA5 via Open-Meteo provides target-night temperature (2m), precipitation, and east/north wind components (100m). Wind direction is converted from the meteorological “from” convention; 100m wind is a proxy, not flight-layer wind. Units are °C, mm/12h and m/s. These are retrospective weather reconstructions, not forecasts available at issue time.

It emitted `blocked-data-quality`, empty metrics and empty predictions. This rejects this extraction, not the complete archive or data-fusion idea. Thresholds were not lowered after seeing the result.

## Comparison implemented behind the gate

1. Seasonal model: intercept + one annual sine/cosine pair.
2. Same seasonal terms + weather.
3. Same seasonal/weather terms + delayed radar density.

All models predict `log1p(density)`, with training-only standardization and ridge regression. Candidate penalties are fixed at 1, 10 and 100. Choose using chronological 2021→2022 validation, refit on 2021–2022, inspect 2023 once. Evaluate on identical eligible nights. The current gate exits before fitting anything.

A lag is eligible only when the entire observation interval ended 48–96 hours before target-night issue time (18:00 UTC). Calendar subtraction is insufficient. Historical publication times were not archived, so this is an assumed availability policy, not proven historical access.

Reported metrics, if the gate passes: log-scale MAE/RMSE, original-unit MAE, relative log-MAE improvement versus seasonal model, and paired seven-calendar-day block intervals with seed 20261008. Intervals would be descriptive for a tiny, one-site test and omit interannual, sensor and species uncertainty. There is no selection of the best test-year model or deployment rule. The target-night ERA5 covariates make this an **oracle-weather historical experiment**, never an operational backtest.

## Next acquisition gate

Inspect missing layers, angular gaps, density flags, nominal timestamps and processing provenance with radar experts. Obtain adequate spring/autumn coverage and multiple locations, preserving the current failed run. A revised extraction is a new protocol version, requiring fresh independent test seasons/sites.
